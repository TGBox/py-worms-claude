# ADR-0008: Rust-Kernel für die heißen Physikschleifen

- **Status:** Angenommen · **Datum:** 2026-11-01 · **Phase:** 1b (zwischen Phase 1 und 2)

## Kontext

Die Simulation läuft in reinem Python. Schon die Wurm-Kollision in Phase 1 hat das Leistungsbudget
gesprengt; es hält nur noch nach gezielten Mikro-Optimierungen. Ab Phase 3 wächst die Last weiter:
Minen, Fässer, Kettenreaktionen, Seil, Läufer, Schwärme und eine KI, die pro Zug Tausende Flugbahnen
simuliert. Fast die gesamte Rechenzeit steckt in wenigen Schleifen: Pixelabfragen,
Kreis-Kollision, Flächennormale, Geschossschritt, Wurmflug und Körper-Kollision.

## Optionen

1. **Ganzen Kern portieren** (Rust oder C#): maximaler Gewinn, aber ein kompletter Umbau. Regeln,
   Waffenbausteine und Missionen wären dann nicht mehr in Python schreibbar.
2. **Rust-Erweiterung mit PyO3/maturin:** sehr komfortabel, braucht aber crates.io und PyPI zum Bauen
   sowie maturin als Build-Backend.
3. **Rust-Bibliothek mit C-Schnittstelle, geladen über `ctypes`:** keine fremden Crates, nur `cargo`.
   Aufrufe kosten etwa 1 µs Overhead, deshalb arbeitet die API grobkörnig (ganzer Geschossschritt,
   ganzer Flug-Frame, Batch von KI-Flugbahnen).
4. **Cython oder Numba:** braucht ebenfalls einen Compiler bzw. eine große Abhängigkeit. Numba
   unterstützt neue Python-Versionen oft erst spät.

## Entscheidung

Option 3. Die Crate `native/` (ohne Abhängigkeiten) baut eine `cdylib` mit `extern "C"`-Funktionen.
`src/core/native.py` lädt sie über `ctypes`. Die bisherigen Python-Implementierungen bleiben als
**Referenz und Fallback** erhalten:

- Fehlt die Bibliothek (kein Rust installiert) oder ist `PY_WORMS_NATIVE=0` gesetzt, läuft das Spiel
  unverändert in Python.
- Beide Wege rechnen **bitgleich**: gleiche Rechenreihenfolge in f64, kein `hypot`/`**` (stattdessen
  `sqrt(x*x + y*y)` und Produkte), Kreis-Offsets kommen aus Python. Paritätstests vergleichen beide
  Wege direkt, ein Determinismustest vergleicht ganze KI-Partien.
- Regeln, Waffenbausteine, Ereignisse und Match-Ablauf bleiben in Python.

Gebaut wird mit `uv run build-native` (ruft `cargo build --release` und kopiert die Bibliothek nach
`src/core/_native/`).

## Konsequenzen

- **Positiv:** Die heißen Schleifen laufen um ein Vielfaches schneller, die KI kann feiner suchen,
  Replays und Determinismus bleiben unabhängig vom Backend.
- **Negativ:** Jede Physikänderung muss an zwei Stellen (Rust und Python) gleich umgesetzt werden.
  Die Paritätstests erzwingen das. Entwickler brauchen für das schnelle Backend Rust
  (rustup + „Build Tools for Visual Studio“ unter Windows).
- Mit Zugang zu crates.io lässt sich später auf PyO3 umsteigen, ohne die Python-Seite zu ändern.
